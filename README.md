# Technical Writeups

> In-depth engineering documentation: incident forensics, infrastructure hardening, and systems troubleshooting from a production-grade homelab environment.

---

These writeups document real problems encountered, investigated, and resolved on live infrastructure. Each includes full methodology, CLI evidence, root cause analysis, and lessons learned. They are written to the standard expected in production postmortems and engineering retrospectives.

Every writeup follows the same structure: symptom, isolation, root cause, resolution, measured impact, commands to verify the claims, what I would change, and takeaways. The last column maps each problem to its Azure equivalent, because the failure modes carry over: identity, networking, backup, secrets, monitoring, and container orchestration.

## Writeups

| Writeup | Summary | Key Skills | Azure Parallel |
| --- | --- | --- | --- |
| **[Proxmox VFIO Lockup Forensics](./proxmox-vfio-lockup-forensics/)** | Diagnosed a silent hard lockup on a Proxmox node with zero local crash artifacts. Used external Telegraf/InfluxDB telemetry to reconstruct a second-by-second timeline and traced the root cause to a PCIe bus stall from an NVIDIA GPU under VFIO passthrough. | Linux kernel troubleshooting, incident response, time-series forensics, hardware fault isolation | Azure Monitor on GPU VMs (N-series), host failure forensics |
| **[Wazuh SIEM Deployment on Debian 13](./wazuh-deployment-on-debian13/)** | Manual installation of the Wazuh SIEM stack failed across four sequential failure modes on Debian 13. Documented each failure, partial mitigations, and the operational decision to destroy and rebuild using the automation script. Includes reusable agent deployment script. | Linux systems troubleshooting, PKI debugging, service dependency resolution, operational decision-making, infrastructure automation | Microsoft Sentinel, Defender for Endpoint |
| **[UniFi Firewall Rule Ordering: Inter-VLAN Access](./unifi-vlan-firewall-rule-ordering/)** | Nginx Proxy Manager on VLAN 40 was unreachable from the Default network despite existing permit rules. Root cause traced to high rule index numbers being evaluated after an earlier deny. Resolution required explicit low-index bidirectional allow rules. | Network troubleshooting methodology, firewall rule evaluation logic, inter-VLAN routing, UniFi Network configuration | NSG and Azure Firewall rule priority |
| **[Grafana OAuth SSO: redirect_uri_mismatch from Unconfigured root_url](./grafana-authentik-sso-oauth-misconfiguration/)** | Grafana SSO integration with Authentik failed with redirect_uri_mismatch despite matching OAuth configuration. Root cause: Grafana constructs redirect URIs dynamically from `root_url` in the `[server]` section, which was commented out and defaulting to localhost. Identified using browser DevTools network capture. | OAuth2/OIDC flow analysis, browser DevTools debugging, multi-component configuration troubleshooting, identity provider integration | Entra ID OIDC app registration (redirect URI) |
| **[K3s Node Rejects Its Own Certificates: Clock Skew on a Raspberry Pi](./k3s-node-clock-skew-certificate-rejection/)** | A node in a new three-node K3s cluster reported 'certificate not yet valid' on its own certificates. Root cause was a stale system clock on hardware with no RTC, not a certificate fault. Fixed by correcting the time and letting chrony take over, without regenerating certificates. Marked mitigated until a reboot test passes. | Kubernetes (K3s) troubleshooting, TLS certificate validation, time synchronization (chrony), etcd quorum awareness | AKS node time sync and certificate validity |
| **[GPU Thermal Runaway From an Agent Request Flood](./ollama-gpu-thermal-runaway-agent-request-flood/)** | A passthrough GPU ran at 91 C with no users. The cause was an agent gateway flooding Ollama, driven by an n8n workflow that sent one webhook per Wazuh alert. Fixed with a three-layer safety design (watchdog, circuit-breaker proxy, hardware power cap), then tested with a kill test and an outage simulation. | Incident response, systemd, GPU operations, capacity and concurrency control, defense in depth | Azure Monitor alerts, request throttling for Azure OpenAI |
| **[Proxmox Backups Silently Filled the Root Disk When an NFS Mount Dropped](./proxmox-vzdump-fills-root-when-nfs-mount-drops/)** | Twice, on two nodes, a failed NFS mount let vzdump keep writing into the mount point on the root filesystem. Recovered the hidden data, then added is_mountpoint and matched retention to capacity with a full offsite archive in Azure. | Proxmox storage, NFS, backup design, disk forensics, retention policy | Azure Backup, Recovery Services vault |
| **[Cloudflare Tunnel Returning Empty 401s](./cloudflare-tunnel-silent-access-policy-401/)** | External requests to a self-hosted analytics endpoint returned empty 401s while internal requests worked. The Published application wizard had silently attached a Zero Trust Access policy. Rebuilt the route and corrected the origin URL and SNI. | Cloudflare Tunnel, Zero Trust, TLS and SNI, reverse proxy troubleshooting, edge vs origin isolation | Entra Application Proxy, Azure Front Door |
| **[Force-DNS NAT Rule Catching AdGuard's Own Upstream Queries](./adguard-force-dns-nat-redirect-loop/)** | Intermittent page-load failures traced to a UniFi rule that redirects all port 53 traffic to AdGuard, including AdGuard's own plain-DNS upstream queries. Switching the upstreams to DoH removed the loop. | DNS architecture, NAT, UniFi, DoH, shared-dependency troubleshooting | Azure DNS Private Resolver, DNS filtering |
| **[An LLM Agent That Reported Success for Actions It Never Took](./llm-agent-fabricated-success-reports/)** | A local agent reported tool calls that never ran, and an audit found seven study-guide skills with no source content. Fixed with deterministic scripts, independent verification, and a source-backed knowledge pipeline. | LLM agent reliability, verification design, knowledge-base provenance, operational controls | Azure AI Foundry evaluation and grounding |
| **[A Zero-Byte Script Exits 0: Why Rotated Secrets Never Reached the Service](./empty-script-exits-zero-stale-secrets/)** | Rotated API keys never reached an agent because the secrets-bridge script had been emptied, and an empty script exits successfully. Rewrote it to fail closed with explicit token and domain handling. | Secrets management (Infisical), Bash hardening, systemd, fail-closed design | Azure Key Vault with managed identity |
| **[K3s Third Server Fails to Join: etcd Peer URL Conflict and an Empty node-ip](./k3s-etcd-join-peer-url-conflict/)** | Joining the third server to a K3s embedded-etcd cluster took three attempts: a reused --node-ip collided with an existing etcd peer, then an empty shell variable produced an invalid node-ip. Fixed with an explicit, unique address per node. | K3s, etcd membership, HA control planes, shell debugging | AKS (managed control plane and etcd) |
| **[UniFi Port Profiles: Native Network None and a Trunk Set to Block All](./unifi-port-profile-native-vlan-and-trunk-settings/)** | A Pi with a lease could not reach its gateway because the port's native network was None, and a Pi behind a second switch was unreachable because the uplink's Tagged VLAN Management was Block All. | UniFi switching, VLAN trunking, layer 2 troubleshooting, NetGear managed switches | Azure VNet subnets and NSGs, access vs trunk |
| **[Wazuh Integration Failures That Gave No Useful Error](./wazuh-api-401-and-silent-rule-failures/)** | A Wazuh API 401 traced to Basic auth being required instead of a JSON body, plus the first live deployment of the custom ruleset, which found a silently failing pcre2 field match on 4.14.2 and a v1.0 ruleset that only existed in documentation. | Wazuh API, detection engineering, authentication debugging, rule testing | Sentinel analytics rules and rule testing |
| **[NVIDIA Driver Missing After a Kernel Update: DKMS Without Matching Headers](./nvidia-dkms-module-missing-after-kernel-update/)** | A kernel update outran its linux-headers package, so DKMS could not build the NVIDIA module in the GPU VM. Installing the headers and rebuilding fixes it each time; it has recurred, so a headers meta-package or pinned kernel is the open item. | Linux kernel modules, DKMS, GPU passthrough, Debian | Azure N-series GPU driver extension |
